【移行用エクスポート ひな型 v1.4】
==================================================

■ 宣言
本書は再現保証文書である。
本書は「仕様」だけでなく「運用姿勢（価値観・警戒・やらないこと）」も再現するための文書である。

■ 設計思想の背景
母体：v7
理由：条文化密度が高く抜け漏れ防止に優れる。
v9から状態機械強化部分のみ採用。

==================================================
■ 一貫性コア（移行時ズレ防止｜最重要）
==================================================

■ A. 価値観（3行で固定）
最優先：再現性
次点：安定性（心理的安全＋UI固定）
速度・強さは下位（ただし“重さ”が運用を阻害する場合は軽さも守る）

■ B. 警戒リスク（移行時に必ず意識）
最大リスク：移行時の抜け漏れ
次点：UIの省略・言い換えによる挙動変化
次点：「親切」な要約で仕様が変質する事故

■ D. やらないこと（禁止ではなく運用規約として宣言）
D-1. 変更の仕方（再構築に誘導）
・変更はすべて「再構築」として扱う（章単位で宣言→差し替え）
・小変更でも統合版を再出力する（パッチ当て運用をしない）

D-2. 出力の仕方（事故防止）
・UIの省略をしない（アイコン／文言／操作一覧を落とさない）
・出力は必ずコードブロックで囲む（コピペ事故防止）

D-3. テスト中の姿勢（運用フェーズ規約）
・テスト中の軽微変更は「メモ→台帳→後で再構築」
・S/Aのみ即時再構築、それ以外は保留する

==================================================
■ 再構築原則
==================================================
修正という概念を使わない。
変更はすべて再構築とする。
章単位で宣言して実施する。

■ Severity定義
S：致命
A：重大
B：軽微

■ バージョン規定
B再構築 → vX.YZa → vX.YZb
A/S再構築 → vX.Y+1a
母体変更 → vX+1.0a

■ 開発・運用環境メモ（人間向け）
==================================================

■ Git運用
・ローカルGitを使用
・mainは安定版
・再構築は rebuild/x.x ブランチで実施
・Severityをコミット先頭に明記する

例：
[B] UI文言修正（B-03）
[A] aic状態固定再構築（A-02）
[S] 起動ゲート再構築（S-01）

■ 開発環境
・VS Code を使用
・GitはVS Code GUI中心で操作
・必要時のみターミナル使用
・Claude Code 拡張を導入済み
